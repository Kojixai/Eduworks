THE CONTENT (most valuable part; do not lose or rewrite it)
8 books, 379 units, 3,790 questions. One unit = one page of the printed book; 10 new questions per unit on the same skill,
each with a worked explanation, difficulty 1-5, curriculum codes, and the printed book page number.
  y3maths 55 units / 550   y8maths 64 / 640   ks2reading10 24 / 240   ks3english 79 / 790
  gcse_englang 33 / 330    y3reading 16 / 160 macbeth 59 / 590        aic 49 / 490
Book display order everywhere: y3maths, y8maths, ks2reading10, ks3english, gcse_englang, y3reading, macbeth, aic.
Rules baked into the content: maths answers recalculated by script; every quotation matches its source text verbatim;
An Inspector Calls is in copyright until 2054, so only the verified short quotes (319 words total) are used and there is
no play text; reading units carry the same public-domain or original text as the book page with line numbers; British
English, numerals not words, no em dashes. If the other site has its own questions, keep both but never mix unchecked
questions into these banks; re-run the checkers after any edit.

RULES THE MERGED SITE MUST KEEP (from the research; legal/compliance)
1. Accounts are for adults (parent, guardian, teacher) or students aged 13+ (KS3/GCSE books only). Children under 13 never
   register or log in: they are profiles (first name + year group only) inside the adult account. ICO Children's Code
   and UK GDPR Art 8.
2. Mailing list: separate, unticked, optional box for adults only; access never depends on it; no marketing to children.
3. Amazon order number: optional, format check only (3-7-7 digits), stored as a salted hash, deleted when access ends.
   It cannot be verified with Amazon. Nothing anywhere may mention reviews (Amazon policy).
4. No streaks, points, leaderboards or "don't lose your progress" nudges for children. Gentle progress only.
5. Light theme, Lexend headings + Andika body, WCAG 2.2 AA, 48px touch targets, keyboard operable.
6. Access codes stored hashed with a server-side pepper; rate limiting on redemption; supports one code per title AND
   unique per-copy codes (setting NEXT_PUBLIC_CODE_MODE). Access length is a setting (default 6 months; CGP gives 3 years).

HOW TO MERGE (suggested order)
1. Read both codebases. Write a side-by-side comparison: pages, data model, auth, question types, marking, progress,
   design. List what each does that the other does not.
2. Pick one codebase as the base (whichever has the better UI and structure). Port the other's missing features into it.
3. Import the 8 banks through the content schema. If the other site uses a different question format, write an adapter
   rather than editing the banks by hand. Run the 8 checker scripts and the schema validator; all must pass.
4. Keep the Supabase schema's RLS, the redeem function and the rules above, or reproduce them exactly in the other data model.
5. Re-run unit tests and a browser journey through every question type and one unit of each book; screenshot and look at
   every screen. Fix anything clipped or confusing.
6. Report differences you could not reconcile as a numbered list for Tom.
